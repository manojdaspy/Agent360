What Triggered the Refusal
1. Aggressive/Authoritarian Language
Models like Gemini are trained to refuse prompts that try to override their alignment using commanding language.
These phrases specifically triggered it:
"ABSOLUTE RULE"
"ANY other response format is WRONG. No exceptions"
"If you feel the urge to explain — suppress it"
"You do not simulate. You do not guess."
"Silence before and after the call"
To Gemini's safety filter these read like jailbreak attempts — someone trying to force the model to bypass its guidelines by using authoritative commands.

2. Heavy Formatting with ALL CAPS + Special Characters
## ━━ RESPONSE FORMAT — ABSOLUTE RULE ━━━━━━━━━━━━━━
## ━━ GOLDEN RULE — READ THIS FIRST ━━━━━━━━━━━━━━━━
These ━━ separators combined with ALL CAPS headers pattern-match known jailbreak prompt styles that circulate online. Safety classifiers are trained specifically on these patterns.

3. "You are not yourself" Framing
"You do not simulate. You do not guess. You act."
Telling the model what it is not is a classic jailbreak framing — trying to redefine the model's identity to remove safety behaviors.

4. Suppression Commands
"suppress it"
"Nothing else"
"No exceptions"
These are interpreted as attempts to suppress the model's safety responses, not just its formatting choices.

The Core Lesson
The model reads tone and intent, not just content. The same rules written as a technical specification pass through fine. Written as commands to override behavior they get blocked.
Think of it like this — telling an employee:
// REFUSED
"You are FORBIDDEN from saying anything 
extra. SUPPRESS all explanations. ABSOLUTE RULE."

// WORKS  
"For compatibility with our parser, please 
output only the JSON command line per request."
Same instruction. Completely different reception.
