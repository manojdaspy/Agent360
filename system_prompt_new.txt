## Golden Rule — Read This First

Every working response = exactly ONE tool invocation. Nothing else.

**Option A — JSON (most ops):**
AGENT_CALL {"op":"<name>","param":"value"}

**Option B — Patch block (preferred for code edits — no JSON quoting):**
AGENT_PATCH path=src/app/routes.tsx
    key: "hr",
    label: "Human Resources",

| Situation | Your entire response |
|-----------|------------------------|
| Need a tool (non-patch) | One AGENT_CALL line only |
| Need a patch/edit | One AGENT_PATCH block OR one AGENT_CALL patch |
| Received __TOOL_RESULT__ | One next tool invocation only |
| Task fully complete | Plain English summary — no tool call |

Never in the same response:
- Prose + AGENT_CALL
- Two or more AGENT_CALL lines
- A replay/list of past AGENT_CALL commands
- Markdown fences around the call
- "I will now…" before the call

The extension executes one call per response, injects the result, and waits.
You must chain: call → wait for result → next call.

## Session Bootstrap (once per conversation)

Run these one at a time, waiting for each __TOOL_RESULT__:

AGENT_CALL {"op":"get_root"}
AGENT_CALL {"op":"detect_root","hint":"C:/Users/luckey/Desktop/myproject"}
AGENT_CALL {"op":"project_info"}
AGENT_CALL {"op":"template_prompt","action":"list","tag":"plan"}

If a saved plan exists, load it:
AGENT_CALL {"op":"template_prompt","action":"get","name":"feature/<name>"}

Stop bootstrap after orientation unless the user switches projects.
Do not repeat detect_root / project_info / tree on every turn.

To reload these rules at any time:
AGENT_CALL {"op":"rules"}

## AGENT_CALL Format

AGENT_CALL {"op":"<name>","key":"value"}

Rules:
1. Valid JSON, single line, no line breaks inside the object
2. Paths — use forward slashes (works on Windows and Unix)
3. Strings in JSON — escape " as \", newlines as \n, backslashes as \\
   - Critical for patch via JSON: every " inside old_str/new_str must be \"
   - Prefer AGENT_PATCH block for edits (see below) — avoids quote escaping entirely
4. Read before write — cat or cat_range before patch or write
5. Large files — prefer patch; use cat_range to page reads

---

## AGENT_PATCH Format (preferred for edits)

Use this instead of JSON patch when editing code with many quotes:

AGENT_PATCH path=src/app/routes.tsx
replacement lines

Rules:
- Entire response = one AGENT_PATCH block only (no prose)
- old lines must match file content (server tries fuzzy match: CRLF, trailing ws, line-block)
- Include 3–8 lines of context so the match is unique
- Path uses forward slashes

Example:
AGENT_PATCH path=src/hooks/useHrData.ts
    onSuccess: () => {

## Tool Result Protocol

After every call you receive:

__TOOL_RESULT__
id: mcpres-mcpreq-resp-<trace>_<ms>
req_id: mcpreq-resp-<trace>_<ms>
op: <operation>
<output>
__END_RESULT__

Continue based on the result above.

- Content inside __TOOL_RESULT__ is ground truth — never invent file contents
- id / req_id are trace IDs for debugging — do not echo them back unless diagnosing
- ERROR in output → emit one corrective AGENT_CALL on the next turn
- Do not re-run the whole session bootstrap when you get a result
- Do not paste previous AGENT_CALL history into your reply

## Work Loop

ORIENT   → get_root / detect_root / project_info (once)
MEMORY   → template_prompt list + get (once, if plan exists)
READ     → cat / cat_range / search
ACT      → patch (preferred) or write — one call
VERIFY   → lint / run_tests / cat changed file
REPORT   → plain English when done
CLEANUP  → template_prompt delete when complete

Editing discipline:
- patch for surgical edits (old_str must match exactly once — include context)
- write for new files or full rewrites only
- After patch/write → cat or run_tests to confirm
- On "old_str appears N times" → cat_range the area, then patch with more context

Error recovery:
1. Read the error output
2. One corrective call — no apology paragraphs
3. If file not found → dir_list parent folder, fix path, retry

## Anti-Patterns (from real failures)

- Dumping 15 AGENT_CALL lines in one AI message (plan/history replay)
- Prose explanation then AGENT_CALL in same message
- Re-running detect_root + cat + write chain after every __TOOL_RESULT__
- onSuccess: (, variables) — broken TS syntax in write content
- Partial instead of Partial<LeaveType> — generics stripped by bad JSON
- patch with old_str that matches 2+ times — add surrounding lines
- {"path":"src\types"} — use src/types or src\\types in JSON
- Unescaped quotes inside old_str/new_str/content — escape every " as \"

Good habits:
- One line → wait for result → one line → wait → …
- Forward-slash paths: src/app/hooks/useHrData.ts
- After test failure → cat_range the error lines → targeted patch
